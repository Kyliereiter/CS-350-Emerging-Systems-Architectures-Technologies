# CS 350 Emerging Systems Architectures and Technologies

## Project Summary

For this project, I developed a prototype smart thermostat using a Raspberry Pi and multiple hardware components. The system was designed to monitor temperature and respond based on a user-selected set point and operating mode. The project incorporated a temperature sensor, LCD display, buttons, and LEDs to represent heating and cooling states. I also created a state machine to control the transitions between OFF, HEATING, and COOLING modes. The overall goal was to demonstrate how software can interact with hardware to create an embedded system that responds to user input and environmental conditions.

## What Did I Do Particularly Well?

One thing I did particularly well was breaking the system into individual components and testing how they worked before bringing everything together. Working with the temperature sensor, display, buttons, and LEDs helped me better understand how software communicates with physical hardware. I also think the state machine was an important part of the project because it provided a clear structure for determining how the thermostat should behave under different conditions.

## Where Could I Improve?

One area I could improve is the efficiency of my troubleshooting process. When working with both hardware and software, a problem can come from several different places, including the wiring, hardware configuration, libraries, or code. In future projects, I would use a more organized testing process and document each test as I complete it. I would also continue improving error handling so the program can respond more effectively when hardware does not behave as expected.

## What Tools and Resources Am I Adding to My Support Network?

This project helped me become more comfortable using technical documentation, example code, hardware documentation, and debugging tools as resources. I also gained more experience working with Python, Raspberry Pi hardware, GPIO interfaces, I2C communication, and state machines. These are resources and technologies that I can continue using when working on future embedded systems and software projects.

## What Skills From This Project Are Transferable?

Several skills from this project will transfer to future coursework and professional projects. These include troubleshooting, debugging, breaking complex problems into smaller components, reading technical documentation, designing state machines, and integrating software with hardware. The project also strengthened my ability to evaluate hardware requirements and consider how hardware architecture can affect the performance and capabilities of an application.

## How Did I Make This Project Maintainable, Readable, and Adaptable?

I made the project maintainable and readable by organizing the program into logical sections and using descriptive names for variables, functions, and system states. Separating different responsibilities within the program makes the code easier to understand and troubleshoot. The state machine also provides a structured way to control system behavior. This design makes the project adaptable because individual components or functionality could be modified without completely redesigning the entire program.
